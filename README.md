# يمن درايف — تطبيق السائق

تطبيق Flutter عربي لوظائف السائق فقط. يستخدم نفس هيكل تطبيق العميل ومعماريته: Feature-first وGetX للمسارات وBindings وControllers وRepositories وProviders، مع نفس نظام التصميم والاتجاه RTL.

## المتطلبات

- Flutter حديث يدعم Dart `>=3.6.0`.
- Android Studio أو Xcode أو جهاز فعلي مهيأ لتشغيل Flutter.
- خادم ASP.NET يعمل محلياً على `http://localhost:5080` أثناء التطوير.

## التشغيل

```bash
flutter pub get
flutter run
```

لربط بيئة تطوير ASP.NET:

```bash
flutter run \
  --dart-define=FLAVOR=dev \
  --dart-define=API_BASE_URL=https://10.0.2.2:5062/api
```

قيم `FLAVOR` المقترحة هي `dev` و`staging` و`prod`. يزيل `AppEnvironment` الشرطة المائلة الأخيرة من `API_BASE_URL` تلقائيًا.

ملاحظات الاتصال المحلي:

- محاكي Android يصل إلى جهاز التطوير عادة عبر `http://10.0.2.2:<port>/api`.
- محاكي iOS يمكنه استخدام `http://127.0.0.1:<port>/api`.
- الجهاز الفعلي يحتاج عنوان LAN متاحًا وشهادة HTTPS موثوقة في بيئات الاختبار والإنتاج.

## هيكل المشروع

مشروع Flutter هذا مستقل عن الخادم. يوجد مشروع ASP.NET في المجلد الشقيق `../api_control`، ولا توجد ملفات Backend داخل هذا المجلد.

```text
lib/
├── app/
│   ├── bindings/          # الاعتماديات العامة عند بدء التطبيق
│   ├── localization/      # ترجمات GetX العربية والإنجليزية
│   └── theme/             # الألوان والمسافات وثيم light/dark
├── core/
│   ├── config/            # FLAVOR وAPI_BASE_URL
│   ├── network/           # Dio، الاعتراضات، ProblemDetails، endpoints
│   ├── responsive/        # breakpoints وAdaptiveContent
│   ├── services/          # اللغة والثيم
│   ├── storage/           # التخزين الآمن للرموز
│   └── utils/             # validators وDebouncer
├── features/
│   ├── auth/              # البداية، التعريف، التسجيل والدخول والاستعادة
│   ├── ride/              # الحجز، الخريطة، السائق، الرحلة والدفع
│   └── account/           # الملف، المحفظة، العروض، السجل والإعدادات
└── shared/
    ├── models/            # نماذج مشتركة بين الميزات
    └── widgets/           # زر، حقل، بطاقة، Scaffold، حالات وخريطة
```

داخل كل ميزة تُفصل المسؤوليات إلى `views/screens` و`widgets` و`controllers` و`bindings` و`data` و`models` وملف للمسارات. بهذه الطريقة تبقى ملفات الشاشات خفيفة، بينما تنتقل العناصر المتكررة إلى Widgets قابلة لإعادة الاستخدام.

## استخدام GetX

- **المسارات:** توجد القوائم `authPages` و`ridePages` و`accountPages`، وتُجمع في `GetMaterialApp.getPages`.
- **Bindings:** كل مجموعة مسارات تسجل Controllers وRepositories اللازمة فقط. الاعتماديات العامة مثل `ApiClient` و`SecureStorageService` تسجل في `InitialBinding`.
- **الحالة:** القيم المتغيرة معرفة كـ `Rx` وتُرسم الأجزاء المتأثرة فقط باستخدام `Obx`.
- **الترجمة:** النصوص العامة معرفة في `AppTranslations` وتستدعى بصيغة `'key'.tr`.
- **التنقل:** استخدم ثوابت المسارات، مثل `Get.toNamed(RideRoutes.locationPicker)`، ولا تكتب المسار نصيًا داخل الواجهة.

مسار البداية هو `DriverRoutes.login`، وبعد نجاح الدخول ينتقل التطبيق إلى `DriverRoutes.home`.

## وظائف السائق

- الدخول بحساب سائق موجود في قاعدة البيانات.
- تحميل ملف السائق والرحلات المفتوحة المطابقة للخدمة.
- إرسال عرض على رحلة مفتوحة.
- تحديث حالات الرحلة بعد إسنادها.
- إرسال موقع السائق إلى API. الإحداثيات الحالية تجريبية إلى حين ربط `geolocator`.

## الربط مع ASP.NET API

يعتمد `ApiClient` على Dio ويضيف تلقائيًا:

- `Content-Type: application/json` و`Accept: application/json`؛ ترسل الطلبات وتستقبل الاستجابات كـ JSON عادي دون JWE أو غلاف تشفيري مخصص.
- `Accept-Language: ar-SA`.
- `Authorization: Bearer <accessToken>` عند توفر الرمز.
- مهلات اتصال وإرسال واستقبال مناسبة لتطبيق جوال.
- محاولة واحدة لتجديد الرمز عند استجابة `401`، مع منع تكرار عدة طلبات Refresh بالتوازي.

تُحفظ رموز الوصول والتجديد في `flutter_secure_storage`، وليس في `GetStorage`. عقد الخادم التفصيلي موجود في [docs/aspnet_api_contract.md](docs/aspnet_api_contract.md)، وسياسة نقل البيانات الحالية في [docs/payload_transport.md](docs/payload_transport.md). مشروع الخادم نفسه موجود في `../api_control`.

### ProblemDetails

يُفضّل أن يعيد ASP.NET أخطاء RFC 7807 بالنوع `application/problem+json`، متضمنة `title` و`status` و`detail` و`code` و`traceId`، بالإضافة إلى `errors` لأخطاء الحقول. يحول `ApiClient.problemFrom` هذا الشكل إلى `ApiProblemDetails` موحد للواجهات.

### الرموز

- Access token قصير العمر، مثل 10–15 دقيقة.
- Refresh token أطول عمرًا مع rotation وإبطال الرمز السابق عند التجديد.
- إعادة `accessToken` و`refreshToken` بعد الدخول وإكمال التسجيل والتجديد.
- إرسال أوقات الانتهاء بصيغة UTC إذا احتاج العميل إلى التجديد الاستباقي.

### SignalR

يستخدم الخادم الحالي Hub التتبع `/hubs/tracking` لتحديثات السائق والرحلة بدل polling. أهم الأحداث:

- `offerReceived`
- `rideUpdated`
- `locationUpdated`

يرسل العميل access token عبر `accessTokenFactory`، ويضاف الاتصال إلى مجموعة الرحلة بعد التحقق من صلاحيتها. REST يبقى المصدر النهائي للحقيقة عند إعادة الاتصال.

## الوضع الفاتح والداكن

- `AppTheme.light` و`AppTheme.dark` مبنيان من نفس Design Tokens في `AppColors` و`AppSpacing`.
- الألوان داخل الواجهات تُقرأ من `Theme.of(context).colorScheme` قدر الإمكان.
- `ThemeService` يحفظ اختيار المستخدم ويمرره إلى GetX.
- تجنب ألوان النص والخلفية الثابتة داخل أي Widget جديد إلا عندما يكون اللون جزءًا من الهوية، مثل اللون الأصفر الأساسي.

## Responsive وRTL

- أقل من `600px`: هاتف.
- من `600px` إلى أقل من `1024px`: جهاز لوحي.
- `1024px` فأكثر: شاشة واسعة.
- أقصى عرض للمحتوى العام `720px` عبر `AdaptiveContent`، مع Padding متغير حسب العرض.
- استخدم `AlignmentDirectional` و`EdgeInsetsDirectional` بدل `left/right`.
- الشاشات الطويلة والنماذج قابلة للتمرير وتتعامل مع ظهور لوحة المفاتيح.

## إضافة شاشة جديدة

1. أنشئ الشاشة داخل مجلد الميزة المناسب واجعلها تركّز على تركيب Widgets فقط.
2. ضع الحالة والأحداث غير البصرية في Controller، والوصول إلى الخادم في Repository أو Remote Source.
3. أنشئ Binding أو وسّع Binding الميزة لتسجيل الاعتماديات.
4. أضف ثابتًا في كلاس المسارات، ثم أضف `GetPage<dynamic>` إلى قائمة صفحات الميزة.
5. أضف النصوص العامة إلى `AppTranslations`، واستخدم Widgets الموجودة في `shared/widgets` قبل إنشاء بديل جديد.
6. أضف Widget خاصًا بالميزة داخل `features/<feature>/widgets` إذا كان التكرار محصورًا في تلك الميزة.
7. أضف اختبار Smoke أو Widget للحالة الأساسية وحالات الخطأ والتحميل المهمة.

مثال زر مشترك:

```dart
AppButton(
  label: 'continue'.tr,
  isLoading: controller.isLoading.value,
  onPressed: controller.submit,
)
```

## ملاحظات الدمج

- مسارات المصادقة الحالية المقترحة هي `/auth/sign-up/request-otp` و`/auth/sign-up/complete` و`/auth/verify-otp` و`/auth/password/request-reset` و`/auth/password/reset`. عدّل Remote Repository فقط إذا اختلف عقد ASP.NET.
- ملفات `_api_example` توضح نمط ربط مصدر بيانات بعيد، ولا ينبغي استدعاؤها مباشرة من الواجهة.
- لا تضع أسرار الخادم أو مفاتيح الدفع الخاصة داخل Flutter أو `--dart-define`. مفاتيح Google الخاصة بتطبيق الجوال تكون قابلة للاستخراج من APK/IPA، لذلك مررها وقت البناء وقيّدها باسم الحزمة/بصمة التوقيع والواجهات المسموح بها والحصص. اجعل الأسرار الحقيقية على الخادم فقط.
