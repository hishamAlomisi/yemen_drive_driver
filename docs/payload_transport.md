# سياسة نقل البيانات بين التطبيق وASP.NET

تم إلغاء تشفير حمولة الطلبات والاستجابات على مستوى التطبيق بناءً على قرار المشروع الحالي. لا يستخدم النظام JWE أو `application/jose` أو مفاتيح جهاز لتغليف أجسام HTTP.

## القاعدة الحالية

- يرسل Flutter الطلبات مباشرة بصيغة JSON وبنوع `application/json`.
- يعيد ASP.NET الاستجابات بصيغة JSON والأخطاء بصيغة `application/problem+json`.
- يرسل SignalR أحداث JSON العادية دون `payloadJwe` أو نص مشفر.
- يستخدم JWT للمصادقة والتفويض فقط؛ وهو ليس تشفيرًا لجسم الطلب.
- يبقى HTTPS/TLS إلزاميًا خارج التطوير المحلي لحماية البيانات أثناء النقل.
- تبقى كلمات المرور والرموز وبيانات البطاقات خارج السجلات.

## ما تم إيقافه

- لا توجد رؤوس `X-Device-Session-ID` أو مفاتيح تشفير خاصة بالحمولة.
- لا توجد مسارات لتبادل مفاتيح JWE أو جلسات تشفير جهاز.
- لا توجد معالجة `application/jose` أو `payloadJwe` في REST أو SignalR.
- لا توجد أخطاء أو اختبارات خاصة بفك تشفير الطلبات.

## الأسرار المخزنة على الخادم

إلغاء تشفير الحمولة لا يعني إلغاء حماية أسرار الخادم. تبقى كلمة مرور اتصال قاعدة البيانات، وحلقة مفاتيح ASP.NET Data Protection، ومفاتيح JWT والإدارة خارج المستودع وتُمرر عبر متغيرات البيئة أو Secret Manager. حماية هذه القيم داخل الخادم لا تغير صيغة الرسائل بين Flutter وAPI.

## التشغيل

استخدم HTTPS في البيئات التي تتجاوز التطوير المحلي، ومرر رمز JWT في رأس `Authorization` عند الحاجة. لا تضع أسرار الخادم أو مفاتيح الدفع الخاصة داخل تطبيق Flutter أو داخل `--dart-define`. مفاتيح Google الخاصة بتطبيق الجوال مرئية بطبيعتها داخل الحزمة، ولذلك يجب تقييدها باسم الحزمة وبصمة التوقيع والواجهات والحصص.
